# R3 실험 가이드 (CodeBERT 임베딩)

현빈이가 맡을 R3 실험 안내서야. 코드는 다 짜여 있어서, 아래 순서대로 실행하고 결과 파일 두 개만 보내주면 돼.

## R3가 뭐야?

우리 프로젝트는 "AI가 올린 PR이 머지될지"를 예측하면서, **코드를 얼마나 깊이 읽느냐**에 따라 성능과 시간이 어떻게 달라지는지 비교하고 있어.

| 단계 | 코드를 읽는 방법 | 결과 (같은 표본, AUC) |
| --- | --- | --- |
| R0 | 코드는 안 보고 겉정보만 | 0.680 |
| R1 | 바뀐 코드를 숫자로 요약 (줄 수, 파일 수, 테스트 포함 여부 등) | **0.719** |
| R2 | 코드에 나온 단어 세기 (TF-IDF) | 0.717 (R1과 차이 없음) |
| **R3** | **딥러닝(CodeBERT)으로 코드의 뜻 읽기** | **← 이번에 할 것** |

- **CodeBERT**: 수많은 코드를 미리 읽고 공부한 AI 모델이야. 코드를 넣으면 그 뜻을 담은 숫자 768개(**임베딩**)를 돌려줘.
- **PCA**: 768개 숫자를 비슷한 것끼리 묶어 128개로 줄이는 방법이야. R2도 128개였어서 개수를 맞춘 거야.
- R3 = R1 피처 17개 + CodeBERT 임베딩 128개. 분류기(XGBoost)와 설정, 표본은 R0~R2랑 완전히 같아.
- **R3가 R1보다 안 좋아도 실패가 아니야.** "딥러닝으로 읽어도 숫자 요약보다 나아지지 않는다"도 그 자체로 중요한 결과야. 숫자만 정확하면 돼.

## 준비물

- 구글 계정 (Colab 무료로 충분해)
- 이 폴더의 파일 두 개
  - `r3_sample.parquet` (약 79MB): 표본 PR 6만 개의 피처와 diff
  - `r3_codebert.ipynb`: 실행할 노트북

## 실행 순서

1. 구글 드라이브의 **내 드라이브**에 `aix_r3` 폴더를 만들고, 위 파일 두 개를 올려.
   (폴더 이름이 다르면 노트북 첫 번째 코드 칸의 `DATA_DIR`를 바꿔야 해.)
2. 드라이브에서 `r3_codebert.ipynb`를 더블클릭 → **Google Colaboratory**로 열어.
3. 위 메뉴에서 **런타임 → 런타임 유형 변경 → T4 GPU** 선택 → 저장.
4. **런타임 → 모두 실행**.
5. 처음에 "Google Drive에 연결" 창이 뜨면 허용해.
6. 기다려. 단계마다 진행 상황이 출력돼.
   - 1단계(기준 확인)에서 `OK  R0`, `OK  R1`이 나와야 해. `확인 필요`가 나오면 거기서 멈추고 하랑이한테 화면을 보내줘.
   - 2단계(임베딩)가 제일 오래 걸려. T4 GPU 기준으로 수십 분 정도 걸릴 것 같아(아직 직접 재 본 시간은 아니야).
7. 끝나면 드라이브 `aix_r3` 폴더에 **`r3_results.json`, `r3_preds.parquet`** 두 파일이 생겨. 이 두 개를 하랑이한테 보내면 끝이야. 마지막 칸에 나온 결과 표도 캡처해서 같이 보내줘.

## 중간에 끊기면?

Colab은 오래 켜 두거나 창을 닫으면 연결이 끊길 수 있어. 그래도 괜찮아. 임베딩은 2,000개마다 드라이브에 저장되니까, 다시 **런타임 → 모두 실행**을 누르면 계산해 둔 부분은 건너뛰고 이어서 해.

## 자주 나오는 문제

| 증상 | 해결 |
| --- | --- |
| `계산 장치: CPU`라고 나옴 | 3번(런타임 유형 T4 GPU)을 다시 하고 처음부터 실행 |
| `CUDA out of memory` 오류 | 첫 번째 코드 칸의 `BATCH = 64`를 `32`나 `16`으로 바꾸고 다시 실행 |
| `xgboost 3.2가 아니면...` 오류 | **런타임 → 세션 다시 시작** 후 다시 **모두 실행** |
| `r3_sample.parquet`를 못 찾음 | 드라이브 폴더 이름과 `DATA_DIR`가 같은지 확인 |
| GPU 사용 한도 초과 | 몇 시간 뒤에 다시 하면 돼. 저장된 부분부터 이어서 해 |

## 시간이 남으면 (선택)

- `MAX_LENGTH = 512`라서 지금은 diff 앞부분만 읽어. diff를 512토큰씩 나눠 여러 번 읽고 평균 내면 더 많이 읽을 수 있어(대신 시간이 몇 배 걸려).
- PCA로 줄이지 않고 768개를 그대로 붙여 보는 것도 비교해 볼 만해.
- 이런 걸 해 보면 결과 파일 이름을 바꿔서(예: `r3_results_768.json`) 같이 보내줘.
